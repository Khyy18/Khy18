## Что нужно построить

### Архитектура (high-level)

```
[OKX Market Data] (websocket, 7 пар)
        ↓
[Feature pipeline] (классическая система — 50+ features)
        ↓
   ┌────┴────┬─────────┐
   ▼         ▼         ▼
[LSTM]   [LightGBM]  [PPO]    ← три ML-модели
direction regime+size  timing
   │         │         │
   └────┬────┴─────────┘
        ▼
[Decision Aggregator] (система — формула)
        ↓
[Risk Manager] (система — жёсткие правила)
        ↓ APPROVED
[Order Engine] (система — OKX API)
        ↓
[Telegram bot] (существующий UI на 80%)
```

### Принципы разделения

**ИИ решает (только это):**
1. LSTM — направление и магнитуда движения на 15-60 минут вперёд.
2. LightGBM — текущий market regime + multiplier для размера позиции [0..1].
3. PPO — timing исполнения (limit vs market, ждать или сейчас).

**Система решает всё остальное:**
- Все жёсткие правила риска (stop-loss, take-profit, kill-switch, GLOBAL_RISK_CAP).
- Конкретный qty в долларах (формула `risk_amount / stop_distance × multiplier`).
- API-исполнение, retry, обработка частичных fills.
- Telegram UI, мониторинг, логирование.
- Fallback при деградации ИИ.

### Fail-safe механики (обязательны)

1. **Без сигнала от LSTM** → новые сделки не открываются.
2. **При деградации ИИ** (Sharpe < 0.3 на 30-day rolling) → автоматический fallback на простую стратегию или DRY_RUN.
3. **При недоступности Groq** → AI-Gate fail-CLOSED, новые сделки блокируются (как сейчас).
4. **Закрытия работают БЕЗ ИИ** — stop-loss, take-profit, time-stop срабатывают сами.
5. **Auto-pause** при 3 LOSS подряд на паре (существующий механизм auto-block).

## Phased план разработки

**Не делать всё разом.** 6 фаз с чекпойнтами.

### Фаза 0: Baseline и инфраструктура (1 неделя)
- Скачать 1m OHLCV за 2 года по 7 парам (через OKX history-candles, кэш в SQLite).
- Скачать funding rates за 2 года.
- Подготовить feature engineering pipeline (50+ features).
- Запустить простой baseline без ML (например, RSI + ADX на 5m) → получить точку отсчёта Sharpe.

### Фаза 1: LSTM/Transformer pilot (3-4 недели)
- Тренировка одной модели на BTC-USDT-SWAP (одна пара для скорости).
- Walk-forward с 5+ окнами (train 18 мес / test 6 мес).
- Цель: получить честный OOS Sharpe.
- **Чекпойнт:** если OOS Sharpe < 0.4 на pilot — стратегия не работает на этих данных, остановить, обсудить с пользователем.

### Фаза 2: LightGBM regime + sizing (2-3 недели)
- Добавить regime detection поверх LSTM.
- Position sizing через multiplier.
- **Чекпойнт:** Sharpe должен подняться vs Фаза 1.

### Фаза 3: PPO execution (2 недели)
- Обучить PPO на симуляции 2-летних тиков для оптимизации timing.
- **Чекпойнт:** snippet improvement on slippage 5-15% (метрика реалистичная).

### Фаза 4: Multi-symbol + risk integration (2-3 недели)

- Интегрировать с существующим risk manager.
